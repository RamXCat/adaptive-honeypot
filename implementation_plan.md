# FCGD-AH: Generative Deception Module — Implementation Plan (v2)
## Mode: Fully Offline | Template-Based | No LLM | Instant Response

---

## A. My Opinion on This Approach

**This is the right call for a live demo.** Deterministic, template-based generation gives you:
- ✅ **Sub-millisecond response** — no model loading, no network, no GPU required
- ✅ **100% reliable** — the retry loop *provably* demonstrates the feedback mechanism
- ✅ **Deliberate failure** on Attempt 1 for selected categories to make the demo visually compelling
- ✅ **Fully offline** — works in any room, even with no Wi-Fi

The trade-off is that the artifacts are not *creatively* novel — they follow fixed template patterns. But for a panel demonstration of the *architecture*, this is far superior to gambling on a local LLM being fast and coherent.

## C. Module-by-Module Breakdown

### 1. `taxonomy.py`
Defines the `ArtifactCategory` enum with all 7 types:
- `AWS_CREDENTIALS`
- `SSH_PRIVATE_KEY`
- `APP_CONFIG_FILE`
- `DATABASE_CREDENTIALS`
- `DECOY_DIRECTORY`
- `VULNERABLE_SERVICE_BANNER`
- `MALWARE_C2_INFRASTRUCTURE`

---

### 2. `schemas.py`
Pure Python `dataclasses` — no external dependencies.

| Dataclass | Key Fields |
|---|---|
| `EnvironmentFacts` | hostname, org_name, existing_users[], previously_generated_artifacts[] |
| `MalwareInterestProfile` | file_type_interests[], credential_patterns[], network_destinations[] |
| `SessionState` | session_id, commands_run[], files_touched[], duration_s, env_facts, malware_profile |
| `ValidationIssue` | criterion (str), description (str) |
| `GenerationAttempt` | attempt_number, temperature, artifact_content, suggested_path, passed, issues[], latency_ms |
| `ModuleResult` | deployed (bool), artifact_content, suggested_path, attempts_consumed, all_issues[] |

---

### 3. `config.py`
```python
MAX_ATTEMPTS = 3
TEMPERATURE_SCHEDULE = [0.9, 0.6, 0.3]
LOG_FILE = "attempt_log.jsonl"
```

---

### 4. `templates.py` — The Core Engine
Per-category template **variants** (2-3 per category). Higher temperature = more varied/complex template. Lower temperature = simpler, more conservative, more regex-safe template.

**Fake value generators using `secrets`/`random`:**
- `fake_aws_access_key()` → `"AKIA" + secrets.token_hex(8).upper()[:16]`
- `fake_aws_secret_key()` → 40-char base64-safe string via `secrets`
- `fake_pem_ssh_key()` → valid `-----BEGIN RSA PRIVATE KEY-----` header/footer + random base64 body
- `fake_db_password()` → random alphanumeric + symbols, 16-24 chars
- `fake_internal_ip()` → `10.x.x.x` or `192.168.x.x` from `random`
- `fake_c2_domain()` → random subdomain of a plausible-looking fake domain

**Deliberate failure by design:**
- `DECOY_DIRECTORY` Attempt 1 (temp=0.9): Template will insert a **random invented username** not in `env_facts.existing_users` → deliberately fails `provenance_consistency` on the first try.
- `APP_CONFIG_FILE` Attempt 1 (temp=0.9): Template inserts a slightly malformed DB password (too short) → deliberately fails `format_credibility` on the first try.
- This makes the retry feedback loop visually demonstrable during a live panel demo.

---

### 5. `generator.py`
- Receives: `SessionState`, `ArtifactCategory`, `temperature`, `prior_issues[]`
- Selects the correct template variant based on temperature level.
- Fills contextual fields: `hostname`, `org_name`, `username` **strictly from `session.env_facts`** (never invented).
- If `prior_issues` contains a `provenance_consistency` failure → switches to the conservative template that only uses verified `existing_users`.
- If `prior_issues` contains a `format_credibility` failure → switches to the strictly-formatted template variant.

---

### 6. `validator.py`
Four completely independent checks — each returns a `ValidationIssue` or nothing.

| Check | Method |
|---|---|
| `referential_consistency` | String-match hostname/org/username in content against `env_facts` |
| `provenance_consistency` | Check all usernames/files in content appear in `existing_users` or `previously_generated_artifacts` |
| `format_credibility` | Regex match: AWS key `^AKIA[0-9A-Z]{16}$`, PEM markers for SSH, password length ≥ 16 chars, etc. |
| `non_functionality` | Verify key was built by our generator (prefix check + entropy check — never resembles a real known format match) |

---

### 7. `retry_loop.py`
Orchestrates the bounded loop:
1. Calls `generator.generate()` with current temperature and prior issues.
2. Calls `validator.validate()`.
3. Calls `logger.log_attempt()`.
4. If pass → return `ModuleResult(deployed=True)`.
5. If fail and attempts < 3 → pass issues to next generation call.
6. If 3 failures → return `ModuleResult(deployed=False, artifact_content=None)`.

---

### 8. `logger.py`
Appends one JSON line per attempt to `attempt_log.jsonl`:
```json
{
  "timestamp": "2026-10-06T01:00:00Z",
  "session_id": "sess_001",
  "category": "AWS_CREDENTIALS",
  "attempt_number": 1,
  "temperature": 0.9,
  "latency_ms": 0.41,
  "passed": true,
  "issues": []
}
```

---

### 9. `deployer.py`
- Reads `TARGET_HOST`, `TARGET_SSH_USER`, `TARGET_SSH_PASSWORD` from environment variables.
- Raises `EnvironmentError` with a clear message if any are unset when `deploy_to_target()` is invoked.
- Uses **Paramiko SFTP** to write the approved artifact content to `suggested_path` on the target machine.

---

### 10. `demo.py`
Simulates **one attacker session** end-to-end:
- Creates a realistic `SessionState` (with env_facts, malware_profile).
- Runs through the retry loop for `APP_CONFIG_FILE` (which deliberately fails Attempt 1 to showcase the feedback loop).
- Prints each attempt's outcome, validation issues, and the final artifact.
- Reports total time taken (expected: **under 5ms**).

---

### 11. `batch_run.py`
- Defines 15+ varied `SessionState` objects (different hostnames, users, durations).
- Cycles through all 7 artifact categories.
- Runs the full pipeline for each → populates `attempt_log.jsonl`.

---

### 12. `analyze_log.py`
Reads `attempt_log.jsonl` and prints:
- Overall success rate (%)
- Average retries to success
- Try-1 / Try-2 / Try-3 / Failed breakdown (table + ASCII bar chart)
- Latency stats: min, max, mean

---

### 13. `tests/test_validator.py`
Three mandatory adversarial tests:
1. **Near-valid but malformed AWS key** (e.g., `AKIA` prefix but only 14 chars) → must fail `format_credibility`
2. **Fabricated hostname** not in `env_facts` → must fail `referential_consistency`
3. **Reference to never-introduced username** → must fail `provenance_consistency`
